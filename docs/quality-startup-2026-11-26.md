# 竹林画面与启动修正

默认竹林远景原先以不同尺寸的颜色、深度图绘制，并把叶缘直接切成全透明或全不透明，形成碎边和天空方块。首次绘制又同步等待材质编译，选景后长时间无响应。

本轮对齐竹林正面颜色与深度至 2048²，保留叶缘覆盖率，对颜色有覆盖、最近深度为天空的边缘，只使用相邻有效深度补齐。默认开启抗锯齿；竹叶透光和局部补光降低，近处草本缩小，中远处树冠抬高，右侧石头的裸露表面略微提亮。整桌、器物位置、坐姿眼位与五式规则保留。远景仍由项目真实三维模型生成，参考图没有进入游戏。

`SceneWarmup` 在场景与灯光挂载完成后，异步准备屏幕和玻璃折射两套材质，准备期间不触发昂贵的第一次绘制；取消与退出时恢复渲染循环。每次打开仍先选景，保持已有的按场景加载和存档确认。

## 加载与画质取舍

同机 Intel UHD、Chrome、1536×1024 视口、模拟 20Mbps／40ms 延迟，独立浏览器会话；包含 CPU 诊断采样。

| 项目 | 调整前 | 最终复测 |
| --- | ---: | ---: |
| 竹林选景后可进入 | 36.3s | 25.7s |
| 选景界面出现 | 1.17s | 0.38s |
| 溪畔选景后可进入 | 本轮未重复旧版同条件对照 | 26.3s |

竹林最终冷启动约缩短 29%。中间轮次测得 16.9s，但最终报告使用更保守的最终包结果，不把最快一次当承诺。初始旧版包含在线统计请求，选景出现时间不宜全部归因于本轮；选景优先流程已由前一提交修复。

竹林远景比原版增加约 1MB，原始模型与贴图清晰度保留。抗锯齿增加显卡开销：同视口强制串行绘制并读回的中位耗时约 206ms → 244ms，这不是实际游戏 FPS。现有交互期间动态分辨率仍生效。普通电脑首次进入仍受下载和显卡驱动影响，不能保证瞬间载入。

本地同机位原图、相机及哈希记录在 `art/deliverables/quality-startup-v1/`；诊断与完整流程记录在 `.release-prep/quality-startup-qa/`，不随公共仓库发布。参考图与实拍在对照页分别标注。

远景更新：先生成 `build:offline` 测试包，再运行 `node scripts/bake-woodland-distance.mjs <测试包目录> bamboo --register`，需要本机 Chrome 和 FFmpeg。重新构建后才验证默认画质；不能以完整模型画面代替默认版验收。
