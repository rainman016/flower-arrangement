# 三维场景画质与运行负担优化

用户已确认本轮方案：保留整桌、器物、眼位、真实近景与完整环视；减少重复加载和运行时生成，在性能预算内重新组织正面植被。候选验证通过后再合并、发布。

## 边界与结构

- 保留现有 Three.js / React 主 Canvas 和五式规则。
- 发布准备好的三维环境包，包含实际可见几何、实例、材质、静态遮挡及材质扩展。默认画质直接装配，完整原始场景仅供制作与回退使用。
- 环境风动、相机相关投影和器物阴影保持运行时更新；水面需要保持实时视角一致。
- 分离测量：冷加载、装配、材质准备、持续操作帧耗时；不用同步 GPU 读回结果推算 FPS。
- 同机位前后图和八向环视同时验收。重新分配正面植物的高低、疏密，避免靠增加数量弥补层次。

## 待验证门槛

现有 Intel UHD 测试机、20 Mbps / 40 ms：选景 ≤0.5 秒；三次冷加载中位 ≤12 秒、最慢 ≤15 秒；缓存进入 ≤5 秒。持续操作至少五分钟，95% 帧 ≤33.3 ms、99% ≤50 ms，排除调试截图但单独记录首次操作与导出停顿。门槛是目标，未测到前不宣称达标。

先完成资源装配样板并与原版做实际图像和性能对照，再扩展至两个场景、校准美术、完成五式和公开入口回归。达不到门槛的候选保留记录，继续定位，不直接发布。
