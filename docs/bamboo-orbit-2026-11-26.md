# 竹林环视修正验收

本轮基于 `ec8b4f0`。解决转身后的裸坡、叶缘发白、部分石头与竹脚未贴地；保留当前整桌、亚麻桌布、器物、玩家眼位和五式交互。

## 实际改动

- `BambooSurround.ts` 复用已有三维原型，按真实地形增加 1,457 个竹丛与低植被锚点，分布在左右和后方。桌侧原有 39 丛植物收低，移除 1 个过近实例；保留正面辨识度较高的蕨丛与小径。
- 112 个石／岩台锚点按变换后的扫描模型底面采样下埋；多竹竿原型分别测量脚点，避免只对齐整丛中心而让坡上竹脚悬空。近处石头保持真实几何到 12 米。
- 默认画质保留近处三维植被，中远处继续使用由真实三维场景生成、带逐像素遮挡深度的六向远景。正面保持 2,048 像素，水平侧面 1,280 像素；没有使用参考图作为背景。
- 白边根因是覆盖率抗锯齿后又写入半透明画布 alpha，浏览器合成时反向放大了叶缘颜色。主画布保留背景 alpha；无 MSAA 的水面／玻璃目标使用颜色混合并保留目标 alpha。默认与低画质四向画布的异常透明像素均归零。
- `WDS4` 保留原色彩图、测量网格与捕捉眼位，仅把六张遮挡图和阴影图改为更小的无损编码。打包器逐张解码对比完整 RGBA 字节，不相等即失败；读取器仍兼容 WDS1–3。

## 画质与加载取舍

最终竹林包 `bamboo-1944d35df014.bin` 为 4,420,522 字节，比压缩前减少 1,336,099 字节；全部 13 项登记素材共 30,593 KiB，仍低于既有 30 MiB 上限。旧版本和中间包保留在本地，不加入本次新发布文件清单。

Intel UHD 核显、Chrome、1,536 × 1,024 窗口、20 Mbps / 40 ms 冷加载单次实测：

| 指标 | 原版 | 本轮默认 | 本轮低画质 |
| --- | ---: | ---: | ---: |
| 选景界面出现 | 0.32 秒 | 0.37 秒 | 0.32 秒 |
| 选择竹林至就绪 | 26.3 秒 | 27.4 秒 | 27.3 秒 |

补植后的加载略慢，不能声称本轮加速。低画质降低绘制分辨率，资源加载量与默认相同。结果是指定机器单次样本，不代表所有普通电脑。正面林下层次、叶丛形态与光照通透感仍未完全达到参考图；本轮没有修改桌布来迎合旧目标截图。

额外的 `review-quality-startup.mjs` 同机测量：强制 GPU 读回中位耗时由原版 232.4 ms 变为默认 258.6 ms、低画质 206.8 ms。这包含同步读回代价，不能倒数换算游戏帧率。完整流程记录的帧间隔中位数为竹林 29.5 ms、溪景 24.3 ms；切换、首次使用与导出仍有峰值停顿，未宣称稳定满帧。补植增加了绘制负担，未通过删除侧后方内容来隐藏这个取舍。

## 已运行的检查

- `pnpm test -- --reporter=dot`：14 个文件、98 项通过，包括变换后的岩石、斜坡上的多脚竹丛和侧后方补植。
- `pnpm run check:assets`、`pnpm run build`、`pnpm run build:offline` 通过。
- 默认、低画质各真实鼠标转动 8 × 45°，断言经过身后且返回原朝向；各保存入场四向、桌前八向，共 24 张原始实拍，无脚本或着色器错误。
- `verify-five-forms.mjs`：竹林 121 项、溪景 70 项通过，含修剪、插瓶、取出再插回、撤销、刷新恢复、窄屏操作与 PNG 导出。
- `verify-desk-carry.mjs`：器物与花枝拿放、桌面接触、刷新恢复通过。
- `verify-web-entry.mjs`：选景、重试、取消替换、原样续玩、确认新开与手机布局通过。

最初五式回归在撤销倒水后点击失败；未修改的 `ec8b4f0` 同样复现。测试在镜头退回途中投影瓶身，随后真实鼠标点到了桌面。修正为等待实际相机位置与转角稳定，再点击并断言杯子仍在手中、开始按钮可见。未修改游戏交互实现，未放宽断言。
